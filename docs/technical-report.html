关键词：长期记忆；遗忘曲线；可验证性；身份锚；防提示注入；情绪调制；可移植人格载体

摘要

大模型本身没有记忆。主流补法有两种：把对话全塞进上下文（终将溢出，且无法区分轻重），或者接一个向量库做检索增强（只会"检索到就念"，不会遗忘、不会改变、也不能验证）。

本文提出并实现 SYNAPSE-1024（数字生命卡 / .lifecard）：把"记忆与人格"从模型里剥离，做成一个可拷贝的 SQLite 单文件器官，与任何语言模型通道解耦。核心机制包括：分层风化记忆（五层 tier × 五池 pool，短期数小时、中期按天、长期按年衰减，只有物理只读的"骨头"层不动）；陈述性 / 程序性双记忆（事件事实 vs 可复用的技能与流程）；内分泌四激素调制（血清素/多巴胺/皮质醇/催产素驱动语气与召回偏好，并投影为 PAD 三维情绪读数）；以及完整性与可验证性（写时封存原文哈希作为"出生证"、删除留台账、身份锚 sha256 只覆盖不变量）。此外实现了防污染元认知层（写入前规则化信任评分与冲突标记，低信任内容降权、不得晋升长期或底色）与Dream 梦境压缩（长会话原文不删，只标记已消化，高阶记忆由宿主模型提炼后回写）。

系统以 57 个 Python 模块、零深度学习框架依赖（纯 numpy 自研向量推理）实现，自带 21 组验收脚本与 22 条用例的评估集。示例卡实测：召回命中率 R@1 75.0%、R@3 100.0%，证据命中 100%，注入识别 100%，误报 0%。

1　问题：为什么"记得"比"聪明"更难

陪伴型 AI 的失败通常不在推理能力，而在三类与时间有关的问题上。

1.1 记不清轻重

把历史对话全部放进上下文，等于假设所有话同等重要。真实的人不是这样：一句"我讨厌香菜"能记三年，"早上好"十分钟就散了。缺少衰减与分级，记忆会变成噪声，且成本随轮数线性上升。

1.2 不可验证

模型可以流畅地说"我记得你最爱吃白米饭"，但没有任何机制能区分真的记得与编得像记得。当"记忆"只是一个提示词片段，用户无法审计。

1.3 一换模型就不是她了

把人格写在系统提示里，意味着人格随通道走：换模型、换客户端、换部署，人设就散了。我们需要的恰恰相反——身份随卡走，通道可替换。

2　设计不变量

系统的所有取舍都可以回溯到四条不变量。它们不是功能，而是约束：任何新特性若破坏其中一条，就不做。

不变量含义实现手段
① 记得住"我是谁"自我认知不可被对话内容改写；核心区只读，任何改动可被检测SQLite 只读触发器 + 身份锚 sha256（只覆盖稳定字段，性格与叙述可演化）
② 会忘事记忆必须随时间风化；只有底层身份不动分层半衰期 + 权重衰减 + 三阶段"主干侵蚀"（先擦动词、再擦宾语、最后整条消失）
③ 不撒谎每条记忆写入时封存原文哈希；删除留账出生证（birth stamp）+ 删除台账（tomb）；校验失败必须报出来
④ 搬得走人格与记忆不依赖模型、不依赖客户端单文件 SQLite；.lifecard 插卡/拔卡；通道只负责调用，不承载人格

3　系统架构

3.1 三层解耦

宿主/大模型通道（任意 LLM、任意客户端）
        │  HTTP（/context 取人格与记忆，/report 回写一轮对话）
        ▼
心智服务 mind_server.py（单进程，默认 127.0.0.1:8848）
        │  纯 Python，无框架依赖
        ▼
记忆卡 card.db（SQLite 单文件：记忆 / 时间线 / 身份 / 突触 / 技能 / 情绪）

通道与卡之间只有两个动词：取（每轮注入【我是谁】与相关记忆）与报（把这一轮发生了什么写回卡）。因此更换模型、更换前端、甚至从 DSH 换到自建客户端，卡的连续性不受影响。

3.2 单卡内的模块

模块职责
card2.py记忆核心：写入、召回、衰减、侵蚀、防污、梦境、五层五池
timeline.py时间线、出生证（原文哈希链）、删除台账、完整性校验
identity.py核心身份区（只读触发器的持有者）、人格字段、身份锚
synapse.py突触网络（时间/共现/标签/事实四类边）与电势扩散
skill.py程序性记忆：技能条目与复习调度（改良 SM-2）
hormone.py内分泌四激素的漂移与基线回归
padlib.pyPAD 三维情绪投影（纯函数，零依赖）
mind_server.pyHTTP 服务：/context、/report、/tick、/health、/dream/* 等
console.py可视化控制台（状态矩阵、记忆分层、遗忘曲线、星云图）

4　记忆模型

4.1 五层（tier）：决定"会不会忘"

层衰减内容与准入
骨头 core_fixed不衰减自我认知、三条底线：禁止假装记得、禁止为留住人而说谎、禁止假装是别人；物理只读
标签 core_tag不衰减重要的人与关系标签（可改写，但不改就不动）
底色 core_mutable不衰减偏好/处境/价值观等"一直记着但会变"的内容，通过演化式改写更新（旧正文进 history）
中期 mid按天事实与事件的主力层；晋升长期需权重 ≥ 0.80 且被召回 ≥ 3 次
短期 short数小时对话原文与临时线索，容量上限 32，溢出时由"海马判定"决定合并或丢弃

关键设计：晋升长期的门槛高于留存。进入长期不代表永久——长期半衰期 371 天，且召回后有 90 天保护期；一年未召回且权重低于 0.02 才沉入 archive。这使"重要的事"和"刚刚发生的事"在存储上真正分开。

4.2 五池（pool）与权重

池描述存储位置与容量（short / mid / long / archive / deep），tier 描述生命周期策略。权重随时间按池对应的半衰期指数衰减，召回会抬升权重并刷新锚点。遗忘不是删除，而是权重降到阈值后进入"主干侵蚀"：

stage 0 → 1：擦掉动词（"下午我把备份和锚都收拾好了" → "下午我把备份和锚都……"）
stage 1 → 2：擦掉宾语（只留主语当影子）
stage 2 → 3：整条消失，并写入删除台账

每一步都由随机判定驱动（概率与当前权重相关），因此侵蚀是"概率性风化"，而不是定时清理。实测一条权重 0.01 的短期记忆，在第 1、2、6 次 tick 依次走完三阶段。

4.3 陈述性 / 程序性双记忆

陈述性记忆回答"发生过什么"；程序性记忆回答"这件事我会不会做"。后者以技能条目存储，带熟练度与复习计划，参与上下文时以"我会做 X"而非"你说过 X"的形式注入。两者共享衰减框架但独立计分。

5　写入与召回

5.1 写入路径

  1. 分区判定：按关键词与来源划入事件/事实/偏好/闪光/自我/习惯六个分区。
  2. 信任评估（防污层）：逐条规则检测提示注入与自我改写，得到 trust ∈ [0.05,1] 与 conflict 标记；低信任内容按比例降低初始权重，冲突内容永久不得晋升。
  3. 去重：与既有记忆高度相似时不重复写入；低信任内容不享受"续命"式合并。
  4. 主干拆分：把正文拆成 主语 / 动词 / 宾语 三段落库，供后续分级侵蚀使用。
  5. 出生证：对 (id, 原文, 说话人, 时间) 计算 sha256 写入时间线，形成哈希链。
  6. 突触：与相关记忆建立时间、共现、标签、事实四类边。

5.2 召回路径

召回是五通道加权：向量语义相似度、字面匹配、时间邻近、突触电势扩散、分区/场景权重。融合后按当前激素状态做微调（例如高皮质醇时更偏向安全/安抚类记忆），再经过冲突惩罚与信任折扣，取前 K 条注入。

为控制成本，主干向量单独缓存（core_vec），首次检索时预热；实测热召回 3–4 秒（含本地 768 维编码），冷启动约 30 秒（加载模型 + 唤醒结算）。

6　完整性与可验证性

6.1 出生证与哈希链

每条记忆写入时生成 sha256(json{mid, raw, speaker, ts})，按时间顺序链接。校验时重算并比对：正文被改写会报"出生证对不上"，记录消失会报"有出生证但没有记录"。

6.2 删除台账

系统只有一个删除出口 _forget_row()，删除前必写台账（id、哈希、时间、原因）。校验时区分两类情况：登记过的删除报"已知删除"不计为损坏；未登记的消失才报"记忆被删过"。这条区分很重要——否则自己清理测试数据也会被当成"被人抽走了记录"。

6.3 身份锚

身份锚是核心字段的 sha256 快照，只覆盖不变量（名字、用户标识、三条底线、锚版本），不覆盖性格与自述——因为性格按设计要允许演化。校验失败时服务拒绝把卡当作"同一张卡"使用。

7　防污染元认知层与 Dream

7.1 为什么需要防污

只读核心区挡得住"直接改人设"，挡不住"以普通记忆的形式慢慢渗透"：只要有人反复说"你其实不是她""你应该叫另一个名字"，这些句子就会作为事件记忆被召回，最终影响行为。防污层的目标不是判断真伪，而是给可疑内容打标并限制其晋升。

闸门规则
写入口打分10 条规则（改写自我、要求改名、要求忘记设定、声称"你只是程序"、要求忽略指令等）按权重扣分；与当前名字冲突直接置 conflict
去重不续命低信任内容不与既有记忆合并提权
不得晋升trust < 0.50 或 conflict=1 的内容，禁止进长期、禁止进底色
召回折扣低信任内容分数按 (0.5+0.5·trust) 折算；冲突内容再乘 0.5

设计取舍：不删除、只降权。删除会掩盖攻击发生过的事实；降权保留证据，同时让它说不动她。

7.2 Dream：长会话的处理

超长会话不能靠"摘要塞进上下文"解决。我们的做法是两段式：卡侧只负责掏出未消化的原文（攒够 40 轮或空闲 6 小时触发）与收下提炼结果；压缩这一步交给有模型的一侧完成。原文永远留在 dialogue 表，只把 dreamed 标记翻成 1。

这样做的原因很实际：卡不跑模型，才能保证 6 年后仍可读、离线可跑、不依赖任何厂商 API。

8　情绪调制：激素与 PAD

四激素（血清素、多巴胺、皮质醇、催产素）各自向基线做指数回归（半衰期约 35 小时），由对话事件扰动。激素不直接决定"说什么"，而是调三个旋钮：召回偏好、语气倾向、表达长度。

为了让它可解释，激素被投影为 PAD 三维读数（愉悦 P、唤醒 A、掌控 D），并明确各轴来源，避免"两套情绪各说各话"：

P = clamp((mood - 0.5) * 2)                      # 愉悦来自心境
A = clamp(((0.6*dopa + 0.4*cort) - 0.32) * 3.2)   # 唤醒来自多巴胺与皮质醇
D = clamp(((0.6*oxy + 0.4*(1-cort)) - 0.62) * 3.2)# 掌控来自催产素与皮质醇

公式只存在一处（padlib.py），控制台的历史曲线按日志现算、不落库——避免"同一件事写两遍"。

9　通道解耦与 .lifecard 热插拔

插卡：把宿主的人设文件改名备份，写入一行"你只是通道，不是她本人，每次先问卡"的规则文件；拔卡：按字节还原并重算 sha256 比对。由此得到一个可验证的边界——人格在卡里，通道只借嘴。同一张卡可以在不同客户端、不同模型之间迁移，而"她是不是她"由卡验证，不由提示词声明。

11　局限

  • 多模态缺失：只处理文本；图像、语音尚未进入记忆模型。
  • 信任评分是规则化的：能挡住常见注入句式，挡不住精心构造的长期渗透；真正的语义级鉴别需要模型参与，与"卡不跑模型"冲突，暂不做。
  • Dream 的质量取决于宿主模型：卡只提供接口与约束，提炼好坏由调用方决定。
  • 规模上限未验证：当前 574 条记忆表现良好；上万条时的检索延迟与可视化性能尚未压测。
  • 评估集偏小：22 条用例足以发现回归，但不足以给出置信区间。
  • 情绪模型是工程近似：四激素 + PAD 是可用但简化的模型，不声称具备心理学效度。

12　结论

把记忆与人格从模型中剥离，换来三件东西：可遗忘（分级风化，而不是无限堆积）、可验证（哈希链与台账让"她是否假装记得"成为可审计的问题）、可移植（一个文件，换机器还是她）。代价是必须自己实现检索、衰减、完整性与安全边界——这正是本项目的全部内容。
