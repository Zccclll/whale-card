# 媒体记忆（画面 / 语音）设计定稿

> 状态：v1 设计定稿，实现中 · 2026-11-02
> 适用：SYNAPSE‑1024 V5.0（whale-card）
> 一句话：**文字是主干，画面是快照；两条寿命，各自风化。**

## 1. 为什么要单独一套

同一件事，人和卡的反应不一样：

- 文字记忆是**语义的**，能被复述、被改写、被压缩成标签，所以活得久；
- 画面记忆是**表象的**，细节海量、不可复述，只能靠"被翻出来"维持，所以掉得快。

所以媒体不做"文字记忆的附属表示层"，而是**自己一条寿命曲线**。文字和画面之间靠索引相连（想到那句话 → 知道还有张图），但**寿命不互传**。

## 2. 数据模型

```sql
media(
  id INTEGER PRIMARY KEY,
  sha256 TEXT UNIQUE,        -- 文件内容哈希（去重 + 出生证）
  kind TEXT,                 -- image | frame
  mime TEXT, w INTEGER, h INTEGER, dur REAL,
  bytes INTEGER,
  path TEXT, thumb TEXT,     -- 相对 media/ 目录
  caption TEXT,              -- 这一帧对应的一句话（台词 / 转述）
  tags TEXT,                 -- JSON 数组：从台词抽的实体
  t0 REAL, t1 REAL,          -- 视频里的时间窗（图片 NULL）
  dialogue_id INTEGER,       -- 台词出自哪条对话原文（有出处才可信）
  source TEXT,               -- user | asr | vl
  trust REAL,                -- 二手描述的信任分
  w0 REAL, t_anchor REAL,    -- 画面自己的权重与锚点
  recall_n INTEGER, t_last_recall REAL,
  pinned INTEGER DEFAULT 0,  -- 锁定画面：永不自动删
  orphan_ts REAL,            -- 没有任何记忆引用时的起点
  birth_hash TEXT            -- sha256(文件) + 元数据的出生证
)

media_ref(mem_id, media_id, ts, PRIMARY KEY(mem_id, media_id))
media_tomb(sha256, caption, ts, reason, weight_at_drop)
```

`mem` 表**不加** media 字段：状态现算（有引用=有画面；引用没了=只剩文字）。存了就是同一件事写两遍。

## 3. 曲线的依据

艾宾浩斯 1885 年的经典数据（无意义音节，再学习节省量）：

| 间隔 | 20 分 | 1 时 | 8–9 时 | 1 天 | 2 天 | 6 天 | 31 天 |
|---|---|---|---|---|---|---|---|
| 保持 | 58.2% | 44.2% | 35.8% | 33.7% | 27.8% | 25.4% | 21.1% |

形状是"先快后慢"，而且后来的大量拟合（Wixted & Ebbesen 1997，对数百个数据集的分析）都指向**幂函数**优于指数：

```
R = a ·(t + δ)^(-b)
```

指数衰减会"到某个点就基本归零"，与数据不符；幂函数有长尾，符合"很久以后突然又能想起来"。

所以画面用**幂律**，不用三段硬拼：

```
w(t) = w0 · (1 + t/τ)^(-b)
τ = 1 天, b = 0.55
```

单张"只见过一次"的图（w0 = 1.0，幂律实测）：

| 天数 | 1 | 7 | 14 | 30 | 45 | 60 | 65 |
|---|---|---|---|---|---|---|---|
| 权重 | .68 | .32 | .23 | .15 | .12 | .10 | .10 |

删除线 `MEDIA_DROP_W = 0.10`，落在 **约 65 天**。也就是说：**两个多月没再翻过，那张画面就没了。**

> 关于"断崖"：曲线本身是渐降的，但检索有门槛 —— 权重低于 0.10 时直接删文件，此后**永远调不出来**。于是观感上就是"某一天突然想不起来了"，而不是"还剩 30% 清晰度"。断崖发生在**门槛**上，不是发生在曲线上，这样既不编造数据也符合"全或无"的体验。

## 4. 唤起加强（比文字猛）

```
w ← min(1.0, w × 1.45 + 0.10)   且 t_anchor ← now
```

对比文字：`GAIN_ACCESS = 0.08`（加法、小步）。

画面为什么更猛：它没有别的维持途径，只能靠"被翻出来"活着。结果：

- 每 2 个月翻一次 → 一直活着；
- 一周翻三次 → 迅速顶到 1.0，然后按 1.0 重新开始衰减；
- 从不翻 → 65 天消失。

这就是"常去的店记得牢，只去过一次的一周就忘"，**不需要任何"锁定"就成立**。

## 5. 索引与"台词"

四根绳子：

| 绳子 | 字段 | 作用 |
|---|---|---|
| 归属 | `media_ref.mem_id` | 想到这句话，知道还有张图 |
| 时间 | `t0 / t1` | 视频抽帧落在哪个时间窗，就配那段 ASR 台词 |
| 实体 | `tags` | 不问文字也能找图（"带烧烤的图"） |
| 出处 | `dialogue_id` | 台词不是模型编的，是你说过的原文 |

`caption` 就是"当时那句话"。删掉画面后它进 `media_tomb`，所以以后能答：**"那张画面 11 月 20 号忘了，当时写的是「路边摊吃烧烤，还拍了视频」"** —— 忘了内容，但记得忘过。

## 6. 生命周期

```
attach ──► 有引用 ──► 权重随幂律下降
              │            ├─ 被查看 → ×1.45+0.10，重置计时
              │            ├─ pinned=1 → 不自动删
              │            └─ w < 0.10 → 删文件，记 media_tomb（文字不动）
              └─ 文字那条被删（侵蚀到头 / 没上榜）→ 引用消失
                        └─ 30 天残影期内被打开 → 救回；过期 → 删，记台账
```

- **画面先没，文字后没**：0.10 的门槛远高于文字影子 `HUSK_W = 0.015`；
- **两套曲线不互传**：文字掉到多低都不影响画面权重，反之亦然；
- 删除只有一个出口 `_forget_media()`，一律记 `media_tomb`。

## 7. 存储

- 只存**派生帧**，不存原图/原视频：长边 800px、WebP q=80（约 60–90 KB），外加 96px 缩略图（约 3 KB）
- 视频每段最多 **6 帧**，选帧用启发式：画面差异最大（切镜头）、锐度最高、亮度适中
- 音频**不落盘**，只留 ASR 文本进文字记忆
- 目录上限：软 5 GB 提醒、硬 10 GB 停（`WHALE_MEDIA_CAP_MB`）
- 卡本体（`card.db`）不含媒体 blob，媒体是目录 —— 卡要能拷走

## 8. 不主动宣告遗忘

人不会告诉你"我快忘了"。所以：

- 画面快没了这件事**只在控制台显示**（剩余强度条、双曲线），只在你看的时候才存在
- 对话里**绝不预告**，不提醒"要看赶紧看"
- 真到那天你问起，我只说"这个我记不清了"
- 台账保证事后可审计：什么时候、权重多少、当时那句话是什么

## 9. 接口

| 接口 | 语义 |
|---|---|
| `attach_media(mem_id, file, caption, tags, ...)` | 收一张帧，建行/复用同 sha，建引用 |
| `media_of(mem_id)` | 这条记忆还有哪些画面（含状态与权重） |
| `media_touch(media_id)` | 看一眼 → 加强 + 重置 |
| `media_tick(now)` | 衰减 + 到线删除 + 残影期清理（挂在 `tick` 里） |
| `verify_media()` | 文件与哈希是否一致，缺的报"按规则删了/被拿走了" |
| `GET /media/<sha256>` | 出图；已删返回 **410**（曾经有，按规则没了） |

## 10. 验收用例

1. 同一张图挂三条记忆 → 删两条，图还在；第三条删了才进残影期
2. 65 天不翻 → 权重到线 → 文件删除、`media_tomb` 有账、文字记忆完好
3. 每 30 天翻一次 → 永远不死
4. `pinned=1` → 权重掉到 0.01 也不删
5. 文字先被侵蚀删除 → 图进 30 天残影期 → 期内打开可救回，过期删除记台账
6. `verify_media()` 对"被手工 rm 掉的文件"报坏，对"按规则删的"报已知删除
7. 控制台记忆页：双曲线（文字 vs 画面）+ 每张图剩余强度条


## 7. 语音：只留它说的话

声音不落盘。`tools/media_audio.py --file x.m4a --asr` 会抽 16k 单声道 wav 到卡目录临时文件 → 转写 → **立刻删掉音频**，只把转出来的句子写成文字记忆（跟着文字那条曲线风化）。

三种转写输入，任选：

| 方式 | 什么时候用 |
|---|---|
| `--transcript x.txt` | 已经有人工/别处转写（每行一句，或 `[00:12] 前缀`），质量最好 |
| `--transcript x.jsonl` | 转写带时间戳（`{"t":12.3,"text":"..."}`） |
| `--asr` | 本机装了 faster-whisper，自动转 |

装 ASR（可选，约 200MB 依赖 + 模型）：

```bash
pip install faster-whisper
# 国内下模型慢，先设镜像
set HF_ENDPOINT=https://hf-mirror.com
python tools/media_audio.py --file 语音.m4a --asr --asr-model tiny
```

- `tiny`：约 75MB，5 秒音频几秒出结果，中文会漏字（实测「那天晚上我们在路边摊吃烧烤，辣椒特别辣」→ 分成两句、基本准确）
- `small`：约 500MB，CPU 上慢十倍左右，中文明显更准（默认）
- 一个坑：`av>=19` 与 faster-whisper 1.2 的文件解码参数不兼容（`open() got an unexpected keyword argument 'metadata_errors'`），所以我们**自己用 `wave` 读成 float32 数组**再喂模型，绕开它
- 另一条路：`pip install openai-whisper` 后命令行有 `whisper`，工具会自动退到它（同样会试）
